# HU-01: Verificación criptográfica del token de autenticación

## Origen
- **Componente:** API.
- **Id:** H-API-04.
- **Evidencia registrada en HALLAZGOS.md:** `api/app/main.py:14,20,22` (fila `H-API-04`, línea 8 de `HALLAZGOS.md`).
- **Ubicación actual de la lógica relacionada:** `api/app/security.py:8,11,14,16`.

## Contexto
El hallazgo indica que el token se codifica con Base64, compara un secreto fijo y no verifica una firma. Base64 no autentica el contenido, por lo que puede falsificarse una identidad.

## Ajustes necesarios
- Sustituir la comparación del secreto fijo por verificación criptográfica de la autenticidad del token.
- Obtener la clave de verificación desde configuración, sin incrustar secretos en el código.
- Conservar el acceso de identidades válidas y rechazar tokens no válidos en las rutas protegidas de la API.

## Criterios de aceptacion
- Una prueba con un token firmado con la clave de prueba configurada confirma que se acepta y se obtiene la identidad esperada.
- Una prueba que modifica el contenido o la firma de un token confirma que la API lo rechaza con HTTP 401.
- Una prueba con un token sin firma válida confirma que no se autentica una identidad construida y que la API responde HTTP 401.
- Pruebas con claves de prueba distintas confirman que la validación usa la clave configurada: el token firmado con la clave configurada se acepta y el firmado con otra clave se rechaza con HTTP 401.

## Evidencia esperada
- Componente: API; hallazgo cubierto: H-API-04.
- Salida de pruebas que demuestre los cuatro criterios de aceptación, usando únicamente claves y tokens aislados de prueba, sin incluir sus valores en la evidencia.
- Referencia a la ubicación final de la verificación criptográfica y de su configuración.
